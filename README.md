# КиберКлуб

Учебная информационная система компьютерного клуба. Автор учебной работы: Шамаев И. А., ИСТ-2025. Одно окно WPF, 12 мест, четыре раздела. Проект подготовлен с помощью ИИ; перед защитой следует изучить и проверить исходники.

## Запуск на Windows 10

1. Проверьте версию Visual Studio через «Справка → О программе». Требуется **Visual Studio 2026 (18.0 или новее)** с компонентом «Разработка классических приложений .NET» и SDK .NET 10. Для запуска готовой сборки нужен .NET Desktop Runtime 10. Проект не рассчитан на VS 2019/2022 без изменения целевой платформы. Официальная таблица совместимости: https://learn.microsoft.com/dotnet/core/install/windows
2. Распакуйте весь архив в обычную папку, например `Documents\CyberClub`. Не открывайте решение внутри ZIP.
3. Откройте `CyberClub.sln`. Назначьте `CyberClub.App` запускаемым проектом. Выберите Release и нажмите Ctrl+F5.
4. На главной выберите ПК; в «Сеансы» задайте тариф и нажмите «Начать сеанс». Для завершения выберите строку активного сеанса и нажмите «Завершить выбранный сеанс». Итог появится в «История».
5. В «Тарифы» выберите тариф и введите цену с запятой: `120,50`. Изменение применяется к новым сеансам. Уже открытый сеанс сохраняет исходную цену.

## Команды из папки решения

```powershell
dotnet build CyberClub.sln -c Release -m:1
dotnet run --project CyberClub.App -c Release
dotnet run --project CyberClub.Tests -c Release -- evidence/tests.json
dotnet run --project tools/Metrics -c Release -- . evidence/metrics.json
```

Tests — самостоятельный исполнитель юнит-проверок без внешних пакетов. Он возвращает код 1 при ошибке, печатает PASS/FAIL и сохраняет JSON. Это не xUnit/MSTest: в обозревателе тестов Visual Studio эти проверки не отображаются, `dotnet test` не является командой их запуска. 25 проверок относятся к вычислениям и правилам, 4 проверяют файловое хранение (включая отсутствие файла).

## Архитектура и данные

`CyberClub.Core` содержит модели, Billing, ClubService и JsonStore; `CyberClub.App` — XAML и обработчики одного окна; `CyberClub.Tests` — проверки. Осознанно применяется простой code-behind без MVVM-фреймворка: бизнес-правила вынесены из окна и тестируются отдельно. Интерфейс обновляется методом Refresh.

Данные: `%LOCALAPPDATA%\CyberClub\club.json`. При повторном сохранении предыдущая версия становится `club.json.bak`. Запись выполняется через временный файл и File.Replace. Повреждённый файл не перезаписывается: окно показывает ошибку и блокирует изменения. Закройте приложение, сохраните копию повреждённого файла, затем восстановите `.bak` в `club.json` и откройте программу. Резервная копия содержит только предыдущую версию, это не архив всех операций.

Стоимость = цена часа × число начатых минут / 60 с округлением до копеек. Нулевая длительность стоит 0. Отрицательная длительность запрещена. Время хранится как DateTimeOffset. Открывать два экземпляра с одной папкой данных нельзя: совместная работа и блокировки хранилища не реализованы. Система не блокирует игровые ПК и не принимает банковские платежи.

## Настоящие результаты

`evidence/build.log`, `tests.log`, `tests.json`, `metrics.json`, `ui-checks.log` содержат реальные результаты. PNG `01`–`05` — захват реально отрисованного окна WPF в автоматическом сценарии, без дорисовки данных; системная рамка Windows не входит в захват. Это не фото ручного прохождения. Ручное приёмочное тестирование на своём компьютере выполните по документу ЛР 3. Процент покрытия не измерен и не заявляется.

Повторение проверки окна с отдельными новыми данными:

```powershell
$env:CYBERCLUB_DATA_DIR = Join-Path $env:TEMP ('CyberClub-UI-' + [guid]::NewGuid())
$env:CYBERCLUB_EVIDENCE_DIR = Join-Path $PWD 'evidence'
dotnet run --project CyberClub.App -c Release -- --verify-ui
Remove-Item Env:CYBERCLUB_DATA_DIR
Remove-Item Env:CYBERCLUB_EVIDENCE_DIR
```

## Git и загрузка на GitHub

В поставке есть настоящая папка `.git` и две ветки `main`, `feature/quality`; также поставляется переносимый Git bundle. Авторы технических коммитов обозначены как учебный проект, а не как личные действия студента. Просмотр: `git log --all --graph --oneline --decorate` и `git show <хеш>`.

Публикация ещё не выполнена. На GitHub создайте репозиторий `CyberClub` без README, лицензии и .gitignore. Предпочтительно Private; для проверки преподавателем выдайте ему доступ или используйте нужную ему видимость. Затем замените ВАШ_ЛОГИН и выполните:

```powershell
git remote add origin https://github.com/ВАШ_ЛОГИН/CyberClub.git
git push -u origin main
git push origin feature/quality
```

Если origin уже существует, сначала проверьте `git remote -v`, затем при необходимости примените `git remote set-url origin ...`. Пароль/токен в файлы не вставляйте. Сохраните настоящий снимок страницы репозитория и добавьте ссылку в ЛР 2 и курсовую. До этого требование о веб-сервисе остаётся невыполненным.
